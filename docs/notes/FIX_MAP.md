# Failure → fix map, with token costs (draft for PROPOSAL plan item 3)

Written 2026-10-15 from the pre-registered results (sources in the last column). How to use it: identify the failure from a cheap,
label-free signal, then apply the cheapest fix that removed it in our runs. Tokens are output tokens per problem or instance unless noted.

| Failure (how to recognise it, no labels needed) | Cheapest fix that worked | What did not work | Evidence (accuracy at tokens) | Source |
|---|---|---|---|---|
| **Steering by unneeded helpers**: accuracy drops when a toolbox is in the prompt; samples share the same wrong algorithm (e.g. hull built on `polar_sort`) | a one-sentence algorithm hint; or draft first, then refactor, keeping the version that passes the metamorphic check (M5-V2); for a repeated problem, verify once and reuse | a scope sentence (recovers 2–3% of the harm), System 2 Attention (11 points worse), label-free metamorphic selection (picks consistent wrong programs) | hull 97 → 8% with 2 helpers; hint 94% at 0.6k vs thinking at ≈ 6k; M5-V2 91.5% at 0.8k (Qwen3-32B); reuse 100% on 55 held-out instances | F1, PREREG_M2_M4 / M5, PREREG_V (V1G) |
| **Hidden contract in a needed tool**: failures only on mirrored / clockwise / relabelled copies, or time-window violations of a few tenths | fix the tool (make it orientation-free, non-negative, round up) | a warning in the tool's comment (17–19 vs 46–49 of 60; routing 64–65% vs 94–95%), DRAFT-style self-written docs, a probe-verified behaviour sentence | lattice 9–15 → 46–49 of 60; Delaunay 1–3 → 106–109 of 120; Solomon 60–69% → 94–95% | F2, PREREG_F2R |

| **Varied slips**: samples disagree; programs fail the statement's examples in different ways | sample 3 + the examples (or a metamorphic check); one repair round from the failing example | token confidence (DeepConf, log-probs), MBR-exec beyond the examples (+1 point), approximate oracles (< 1 point) | best-of-3 + check 100% at 0.9k vs thinking 91% at 5.5k (synthetic); repair +5.5 to +7.1 points for +0.8–1.4k; 3 rounds = 3 samples + check at 76% of the tokens (contest) | F4, PREREG_N (N2, N2m), PREREG_B1, C1 |
| **Systematic errors on hard one-off problems**: every sample fails the examples alike; the examples pass many wrong programs | more reasoning effort (escalate only when the examples fail: N3), after one repair round from the failing example (N4: +1.3 points; routing by failure type, i.e. repair only crashes, gains nothing over plain escalation: N7) | metamorphic example augmentation (catches 6%), retrieved solved exemplars (+1.2, n.s.), distilling teacher programs (12.9 → 5.3%) | gpt-oss-120b low / medium / high 46 / 57 / 66% at 3.2k / 6.8k / 30k; ≥ 2300 band 49% only at high; cascade +2.7 points at 13% fewer tokens (20b) | H2c, H2d / H2e, PREREG_N, PREREG_D1 |
| **The same problem repeats over many instances** (routing, scheduling, a fixed geometry task) | verify once, reuse: draw k programs, keep the one that passes a cheap check on a few instances (feasibility; or a few known answers + agreement tie-break), run it on all instances | per-instance generation (7–48%), repair before reuse (luck-dependent; can turn the solver into a greedy heuristic), a portfolio of copies of the same idea | 94–100% on held-out Solomon / job-shop / synthetic; cost ≈ tokens per candidate / share of working candidates (gpt-oss-120b + docs: 94% for 14k in total); transfers to 2× / 4× larger instances (60 / 60) | PREREG_V (V1, V1c, V1x) |
| **Consistent errors pass the cheap check** (the examples / symmetry check accept a wrong program; samples agree on it) | a *different* second opinion: a program written under another tool condition (with vs without helpers / snippets), or a slow brute-force oracle on small generated inputs; escalate to the expensive fix only when they disagree | routing by error type (N10), probing a few instances (N11), the model's own pick of a fix, resampling the same condition (MBR-exec +1) | geometry (Qwen3-32B): 99.1% on 3 seeds at 61–79% of always-thinking's tokens; contest (gpt-oss-120b): medium → high on examples-or-oracle 66.3% @ 24.7k vs always-high 66.2% @ 30.1k; pays only when the escalation target is good for the model (thinking: yes for Qwen3-32B, no for Qwen3.6) | PREREG_N10 (N12), PREREG_N (N13) |

| **Verbose no-think model hits the token cap** (Qwen3.8: half the answers unfinished at 6k / 16k) | raise the cap or lower the effort setting | asking for code only (it moves the reasoning into comments; −14% tokens, −2 points) | no-think 35 → 48% with a 28k cap; thinking-low 44 → 51% | H6, H6b / c / d |
| **Distilling robustness into a fast model** | train on the student's own verified programs and replay them (protects other tasks) | teacher programs (idiom drift), even when commented or limited to solvable problems | synthetic: 77 → 98% under helpers at 0.35k instead of 6k; held-out hull 118 vs 48 of 120; contest: own data neutral, teacher data harmful | F5, E4, PREREG_D1 |

Rules of thumb that cut across rows: (1) read the failure before choosing the fix: crashes and window violations call for facts or a
fixed tool, disagreement between samples calls for sampling + a check, shared errors call for reasoning or a hint; (2) never trust a
single seed for a positive claim (the N6 seed-1 p = 0.03 did not replicate); (3) when a problem repeats, pay once for a verified program.
